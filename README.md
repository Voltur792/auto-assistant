# Авто-Помощник (auto-assistant)

Плагин [Astra](https://github.com/mihailinl/astra) «автоматический помощник»:
сам читает почту по IMAP, отбирает важное и превращает его в дайджест,
задачи и записи в календаре — силами той модели, которая уже настроена
в Astra, без отдельных API-ключей.

## Как это работает

```
IMAP-ящик ──► проверка по расписанию ──► отбор важного
                                            │  белый список / правила / LLM (через чат Astra)
                                            ▼
                                     дайджест во вкладке «Помощник»
                                            │
                              авто-хэндофф или кнопка «Создать задачи через Астра»
                                            ▼
                       Astra создаёт задачу + запись в календаре (или напоминание)
                                            ▼
                    триггер «Важное письмо найдено» → ваши автоматизации (озвучка и т.п.)
```

## Возможности

- **Читает почту сам по IMAP** (Яндекс / Gmail / Mail.ru / свой сервер).
  Встроенная почта Astra доступна только окну Astra — плагины в неё не
  попадают, поэтому плагин ходит на сервер напрямую и только читает
  (`BODY.PEEK` — письма **не** помечаются прочитанными).
- **Отбирает важное** — режим на выбор: белый список отправителей, модель,
  keyword-правила или комбинация (по умолчанию — белый список + модель).
- **Разбирает письма моделью через чат Astra** (`send_chat_message`): берётся
  та модель, что настроена в Astra — локальная или облачная, **отдельные
  API-ключи не нужны**. Если чат недоступен — фолбэк на keyword-правила.
- **Создаёт задачи у самой Astra**: прямого доступа к виджетам у плагина нет,
  поэтому он отправляет сформулированную просьбу в чат Astra, а Астра вызывает
  свои инструменты `add_task` / `add_calendar_event` / `add_reminder`.
  Результат проверяется по спискам задач/календаря Astra и показывается во
  вкладке — модель не сможет «соврать», что создала.
- **Озвучивает ответ Астры** (по желанию, вкл. по умолчанию): после хэндоффа
  Астра произносит вслух, что создала.
- **Сроки — в календарь Astra** (по умолчанию) или в напоминания, или и то
  и другое — переключается в настройках вкладки.
- **Триггер для автоматизаций** «Важное письмо найдено» с полями `subject`,
  `from`, `from_addr`, `summary`, `importance`, `account` — свяжите его с
  любым действием в редакторе автоматизаций Astra.
- **Своя вкладка «Помощник»**: дайджест, ящики, белые списки, режимы.
  Стеклянная тема, подхватывает тему Astra.
- **Экономия токенов**: каждое письмо уходит в модель один раз, явная реклама
  режется правилами до модели, обработанные письма не пересылаются.

## Установка

**Важно про LLM.** При установке плагина **из файла** (`.astraplugin`) Astra
безусловно отказывает праву `send_chat_message` — это потолок доверия для
файлов, пришедших не из реестра. Умный разбор тогда не работает (письма
разбирают keyword-правила, во вкладке будет пилюля
`LLM: право send_chat_message отказано…`).

Чтобы модель работала, ставьте плагин **sideload-ом** (права не урезаются):

```powershell
astra-plugin dev <путь к папке плагина>
```

Нужен включённый «Allow unsigned plugins» в настройках Astra; при регистрации
согласитесь на право `send_chat_message`. Нюанс sideload: плагин не
автостартует после перезапуска Astra — запустите его заново той же командой.

Установка из файла (`.astraplugin`) тоже работает — но без LLM (см. выше).

### Настройка почты

Вкладка **Помощник → Почта → «+ Добавить ящик»**:

- **Яндекс**: id.yandex.ru → Безопасность → Пароли приложений (тип «Почта
  (IMAP)»); затем Настроить → Почта → «Портал IMAP-клиентов» — разрешить
  доступ внешним почтовым программам.
- **Gmail**: включить 2-Step Verification, создать App password для Mail
  (myaccount.google.com/apppasswords).
- **Mail.ru**: Пароли для внешних приложений в настройках безопасности почты.

Адрес + **пароль приложения** (не основной пароль!) + белый список (подстроки
отправителя, по одной в строке). Кнопка «Проверить» — тест подключения,
«Сохранить» — применить. Ящиков может быть несколько — все включённые
проверяются за один проход, у каждого свой статус в списке.

### Автоматизация-уведомление (по желанию)

Настройки → Автоматизации → «+» → *Когда*: плагины → «Важное письмо
(Астра-Помощник)» → *Тогда*: «Произнести» с текстом
`Важное письмо от {from}: {subject}. {summary}`.
Без такой автоматизации триггер срабатывает «в пустоту».

## Настройки (вкладка «Почта»)

| Поле | Что делает |
|---|---|
| Интервал проверки | как часто ходить на IMAP (мин) |
| Режим отбора | белый список / LLM / правила / комбо |
| Разбор моделью (LLM) | просить модель Astra разбирать письма |
| Самой создавать задачи | авто-хэндофф: просить Астру создать задачи по важным письмам |
| Сроки записывать как | календарь / напоминания / и то и то |
| Озвучивать ответ Астры | произносить вслух, что создано |
| Экономия токенов | явную рекламу разбирать правилами, без LLM |
| Белый список | подстроки адреса/имени отправителя; пусто = проходить всем |

Режимы: `whitelist_llm` (рекомендуемый), `whitelist`, `llm`, `rules`.

## Где хранятся настройки и данные

**Не в папке плагина** — та стирается при каждой переустановке, а пароль
приложения почтовый сервис показывает только один раз. Настройки и дайджест
лежат в стабильной папке пользователя:

- Windows: `%APPDATA%\auto-assistant\` (settings.json, state.json)
- Linux: `$XDG_DATA_HOME/auto-assistant/` (или `~/.local/share/...`)

Переустановка/обновление плагина **не требует повторного ввода почт и
паролей**. Старые данные из папки плагина переносятся туда автоматически при
первом запуске. Переменная `AA_DATA_DIR` переопределяет папку (тесты,
переносимые установки).

## Экономия токенов LLM

- **Каждое письмо уходит в модель один раз** — при первом появлении (дальше
  оно в `seen_uids` и не пересылается).
- **Явная реклама минует LLM** (вкл. по умолчанию): письма, которые
  keyword-правила уверенно относят к рекламе («скидки, распродажа,
  рассылка…»), разбирают только правила. Большинство писем — реклама, так что
  основная экономия здесь.
- **Обработанное не отправляется повторно**: после успешного хэндоффа письмо
  получает метку ✓ «задачи запрошены» и больше не попадает в запросы к Астре.
- Все письма за одну проверку идут **одним батчем** — один запрос на проверку,
  а не одно сообщение на письмо (история чата плагина уходит в модель целиком,
  а API очистки чата у SDK нет).

## Инструменты для модели Astra (tools)

`assistant_get_digest`, `assistant_check_mail`, `assistant_handoff` — Астра
может вызвать их сама, если попросить её «посмотреть, что в почте».

## Безопасность

- Используются **пароли приложений** (не основные пароли аккаунтов).
- Пароли хранятся в `%APPDATA%\auto-assistant\` — вне папки плагина,
  переживают переустановку; в git и в пакет не попадают.
- Плагин не отправляет письма и ничего не удаляет — только читает (PEEK).
- Текст писем уходит в модель, настроенную в Astra (локальную или облачную —
  какую выбрали вы).

## Структура

- `src/plugin.py` — точка входа: поллер, tools, actions, trigger, ui_calls
- `src/mailer.py` — IMAP (stdlib `imaplib`, без зависимостей)
- `src/analyze.py` — белый список + keyword-правила + разбор ответа LLM
- `src/store.py` — JSON-хранилище в `%APPDATA%\auto-assistant`
- `ui/` — вкладка (bridge Astra, стеклянная тема)
- `tests/` — pytest (уровень 1: в процессе, без демона)

## Разработка

```powershell
python -m pytest -q
astra-plugin check . --strict
astra-plugin test .
astra-plugin build .
```

Требования Python: только stdlib + `astra-plugin-sdk` (см. `requirements.txt`).

## Известные ограничения

- **LLM доступен только при sideload**: установка из файла отказывает
  `send_chat_message` (см. «Установка»).
- Задачи создаёт сама Astra — для отправки в чат нужно открытое окно Astra,
  и модель решает, что создать (плагин проверяет результат и показывает
  отчёт «(проверка: …)» во вкладке).
- Gmail в РФ требует стабильного доступа к Google — Яндекс предсказуемее.
- Без LLM работают keyword-правила: слова «сдать/презентация/дедлайн/
  оплата/срок» + дата в тексте = важно.
